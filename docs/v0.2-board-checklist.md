## Remaining physical checks

### Controls and harmonic following

1. Connect the Client explicitly and identify the running build. Confirm normal
   pad attacks/releases on USB and DIN before enabling new policies.
2. In Chords, enable Live Update. Compare Keep key notes ON and OFF with C major
   then a different left chord. Only subsequent right-hand attacks should follow;
   held notes must retain their original pitch and release.
3. Enable Mute direct chord. Selecting harmony should silence only the ordinary
   direct left attack; Arp inputs and Pads-source recording still receive it.
4. Exercise key/scale shortcuts, custom scales and Cycle layout. Check that a
   held chord releases correctly after each change, including while strumming.

### Voicing

5. Compare Inversions and Drop voices first. I/II/III retain their established
   mutually exclusive inversion or independent drop behavior and LEDs.
6. In Auto leading, check that I/II/III and context inversion do nothing.
   Changing key/scale, layout or mode and Panic should reset leading history.
7. In Octave fold and Guitar register, check that held notes do not change when
   switching modes. I/II/III and context inversion should stay inactive; the
   recorded Guitar button check does not establish this for every mode.
8. Repeat with Spread, bass octave, transpose, octave layers and one-shot strum.
   Those effects apply after voicing, so the final range can be wider. Check
   releases, sustain, overlap, Arp input and live-pad MPE without stuck notes.
9. Test a seven-distinct-pitch-class chord in Guitar register: it should retain
   the original voicing, with no omitted tone. Right-pad Guitar remains separate.

### Guidance

10. Check source-key snapshots after root/custom-scale changes: reopen Harmony
    guidance to capture the new key, without changing already-held notes.
11. Check Add held notes exclusions with Arps, strumming and sustain, and
    compare Use selected chord. The basic C/E/G and navigation pass does not
    cover these ownership boundaries.
12. Try dense input and more destination families, including a comparison with
    no shared triad. There are 99 advisory families and 70 distinct playable
    catalog families; the recorded examples do not qualify every family.

### Persistence, sequencing and stress

13. Check saved voicing selections beyond the earlier Auto-leading snapshot.
    That snapshot used V15; current V19 imports need their own restoration
    qualification. Older firmware cannot import newer exports. Guidance and
    leading history must reset on restore.
14. Check save/reboot and recall of a nonempty recorded take. The step-entered
    T1 persistence and observed T2 recording/Undo/Redo passes do not establish
    this. Capacity remains 21 tracks, 512 live events, 256 take events and 128
    playback voices, plus the full 512-event undo arena now in SRAM; maximum
    capacity remains unqualified on hardware.
15. Run both Arps and sequencer playback while changing views, playing/releasing
    overlapping chords and browsing guidance. Record any audible stalls, stuck
    notes or control delays. Stack high-water and worst-case foreground latency
    still need measurement on the board.

Record build, settings, route/channel, exact actions and observed result for each
failure. Updater interrupted-recovery, automatic rollback and cross-platform USB
qualification remain separate release milestones; this checklist does not imply
they are complete.

## Earlier live Harmony and scoped reset checks

The earlier `041e3904` build used settings V16. Its first physical Harmony check
confirmed retained chord names after release, suggested-pad highlights and
silent DOWN selection. The checks below were defined for the subsequent V17
ranking/map and navigation redesign. Later full-surface Harmony results follow
in their own section; those focused passes do not establish every boundary
listed here.
Retain the existing backup and update capture workflow. Do not repeat unchanged
checks above unless a regression or changed path warrants it.

1. **Chromatic contrast:** with Key contrast ON, verify the five black-key
   pitch classes dim in Chromatic and All notes. The Chords and Lights controls
   must reflect the same value. Check OFF, then restore ON. In Harmony, check
   that held feedback remains brighter than resting guidance.
2. **Centered leading:** repeat ascending and descending chord cycles in Play,
   then Harmony. Chords should stay near the base octave rather than walking
   toward the MIDI limits. Confirm intentional octave/transpose controls still
   move the register and held notes release through their original routes.
3. **Live Harmony:** enter Engines → Harmony, play a chord and release it. Check
   retained base, varied roots before same-root extensions, up to nine choices,
   silent selection and highlighted pad positions. Fifths is the new default;
   existing saved views remain unchanged. Browse the alternatives with LEFT.
4. **Note input:** compare Chromatic and Chord tones; test Live additions,
   Melody only and Manual capture. A released addition should disappear from
   live analysis, while the retained base remains. Held pitches must not change
   when the map or key changes. Check Freeze and explicit capture separately.
5. **Context controls:** exercise 5's Suggestions/Octaves banks, 12's note map,
   U3's octave target, U1/U2, root previews and supported M-scale previews.
   Previewing must not alter the playing key; only Apply key does. Confirm
   ordinary control behavior returns after leaving Harmony.
6. **Cluster roles:** with the board idle, enable System → Swap clusters.
   Verify chord/note and sequencer editor/input roles, context controls, routes,
   lighting and Client inspection. Physical sensitivity/calibration must stay
   with the same sensors. Reject a role change during held input, then restore
   the desired assignment after release.
7. **Reset options:** start with a small reversible menu change. Confirm the
   shared icon and final-row placement, Cancel default, LEFT/CENTER cancellation
   and explicit RIGHT confirmation. Check selected-instance scope, dedicated
   track return and Client confirmation. Preserve songs, library records,
   calibration and individual overrides; do not use these tests as blanket
   authorization to reset the user's actual settings.
8. **Persistence and load:** save preferences, release everything and compare a
   cold-boot export. Harmony captures and running inputs should be empty after
   boot. Measure dense-chord/Arp/sequencer/display/Client traffic and stack
   high-water before claiming the memory reserve or foreground timing proven.

See [Harmony](harmony.md), [Reset options](reset-options.md) and the final
[resource audit](firmware-budget.md) for behavior and limits.
